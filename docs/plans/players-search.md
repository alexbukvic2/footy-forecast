# Plan: Players — Entity and Search Endpoint

**File:** `docs/plans/players-search.md`
**Date:** 2026-05-22
**Status:** Draft

---

## 1. Goal

Introduce a `players` table (football players, not app users) scoped to a tournament and expose a single authenticated `GET /tournaments/{tournament_id}/players/search?q=<string>` endpoint that returns up to 5 matching players by name using trigram-based fuzzy search.

---

## 2. Out of Scope

- Creating or updating players via the API. Players are loaded by out-of-band data import (a CLI tool or script consuming the api-football feed), not through REST endpoints.
- Pagination beyond the hard 5-result cap.
- A `GET /players/{id}` detail endpoint.
- Deleting or deactivating players.
- Filtering or sorting by team name.
- Cross-tournament player deduplication (the same footballer in two different tournaments is two separate rows by design — see Open Questions).
- Any admin interface for managing player data.

---

## 3. Data Model Changes

### 3a. Schema note: `players.tournament_id` type

The feature spec describes `tournament_id` as `bigint FK → tournaments(id)`. This is incorrect: `tournaments.id` is `UUID`. The FK column must be `UUID` to match the referenced column. **The migration below uses `UUID`.**

### 3b. `players.id` type

UUID, consistent with all other tables. `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`. Serialised as a UUID string in JSON responses.

### 3c. Search approach: `pg_trgm` over `tsvector`/`tsquery`

`pg_trgm` is chosen. Trade-off summary:

- **`tsvector`/`tsquery`** tokenizes by word boundaries and applies stemming. It handles whole-word prefixes like "Ronaldo" → token `ronaldo` well, but cannot match mid-word substrings: `q = "aldo"` would not find "Ronaldo", and `q = "bapp"` would not find "Mbappé". This makes it poorly suited for player name search where partial/substring matches are the primary use case.
- **`pg_trgm`** breaks strings into overlapping 3-character sequences. A GIN index on trigrams accelerates `ILIKE '%q%'` and the `%` similarity operator. Partial substrings, partial prefixes, and mild typos all work naturally. This is the correct semantic fit.
- At the expected scale (≤ ~1200 rows per tournament), both approaches would be fast. `pg_trgm` wins on semantics alone.
- `pg_trgm` ships bundled with Postgres 16 and is available on RDS via `CREATE EXTENSION IF NOT EXISTS pg_trgm` — no additional setup.
- **`unaccent`** is added alongside `pg_trgm` so that `"mbappe"` matches `"Mbappé"`. The GIN index is a functional index on `unaccent(name)` and the query applies `unaccent` to both the column and the parameter.

### 3d. New migration: `migrations/20260522000002_players.sql`

Timestamp must follow the most recent existing migration.

```sql
-- +goose Up
-- +goose StatementBegin

CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS unaccent;

CREATE TABLE players (
    id            UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    external_id   TEXT        NOT NULL,
    name          TEXT        NOT NULL,
    tournament_id UUID        NOT NULL REFERENCES tournaments(id),
    team_name     TEXT        NOT NULL DEFAULT '',
    team_flag     TEXT        NOT NULL DEFAULT '',
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT players_external_id_tournament_uq UNIQUE (external_id, tournament_id),
    CONSTRAINT players_name_length_chk CHECK (char_length(name) BETWEEN 1 AND 200)
);

CREATE INDEX players_tournament_id_idx  ON players (tournament_id);
CREATE INDEX players_name_trgm_idx      ON players USING GIN (unaccent(name) gin_trgm_ops);

CREATE TRIGGER players_set_updated_at
    BEFORE UPDATE ON players
    FOR EACH ROW
    EXECUTE FUNCTION set_updated_at();

-- +goose StatementEnd

-- +goose Down
-- +goose StatementBegin

DROP TRIGGER IF EXISTS players_set_updated_at ON players;
DROP TABLE IF EXISTS players;
-- pg_trgm and unaccent are intentionally left in place on rollback; future objects may depend on them.

-- +goose StatementEnd
```

Notes:
- `id` is `UUID` generated by `gen_random_uuid()`, consistent with all other tables.
- `UNIQUE (external_id, tournament_id)` prevents re-importing the same player in the same tournament while allowing the same external ID across different tournaments.
- `set_updated_at()` already exists from the tournaments migration — no need to redeclare it.
- The GIN index is a functional index on `unaccent(name)` so it is used by the `unaccent(name) ILIKE '%' || unaccent($2) || '%'` query.
- `team_flag` stores raw SVG markup. No DB size constraint is added. The data import pipeline is responsible for limiting input size.
- Both extensions are left in place on rollback — conservatively safe.

## 4. API Surface

### Route

```
GET /tournaments/{tournament_id}/players/search?q=<string>
```

Protected by `authMW` (Cognito JWT validation + JIT user upsert, same as all other protected routes).

### Path parameter

| Name | Type | Description |
|---|---|---|
| `tournament_id` | UUID string | The tournament to search within |

### Query parameter

| Name | Type | Constraints | Description |
|---|---|---|---|
| `q` | string | Required; 1–100 characters after trimming whitespace | Player name search term |

### Success response — 200 OK

```json
{
  "players": [
    {
      "id": 42,
      "name": "Kylian Mbappé",
      "team_name": "France",
      "team_flag": "<svg>...</svg>"
    }
  ]
}
```

`players` is always an array; empty array when no results match (never `null`).

`id` is a UUID string. `external_id` and timestamps are excluded — they are internal details.

### Error responses

| Condition | Status | Body |
|---|---|---|
| Missing or invalid JWT | 401 | `{"error": "unauthorized"}` (from middleware) |
| `tournament_id` not a valid UUID | 400 | `{"error": "invalid tournament_id ..."}` |
| `q` missing or empty after trim | 400 | `{"error": "q must not be empty: invalid"}` |
| `q` longer than 100 chars | 400 | `{"error": "q must be at most 100 characters: invalid"}` |
| Tournament not found | 404 | `{"error": "not found"}` |
| Unexpected error | 500 | `{"error": "internal server error"}` |

## 6. Edge Cases

| Scenario | Handling |
|---|---|
| `q` is empty or whitespace-only | `PlayerService.Search` returns `domain.ErrInvalid` → 400 |
| `q` exceeds 100 Unicode code points | `PlayerService.Search` returns `domain.ErrInvalid` → 400 |
| `tournament_id` path value is not a valid UUID | `parseUUIDPathValue` (existing helper, reused from league handler) returns `domain.ErrInvalid` → 400 |
| Tournament UUID is valid but does not exist | Service calls `TournamentGetter.GetByID`, receives `domain.ErrNotFound` → 404 |
| Zero players match the query | Repository returns `[]*domain.Player{}` (never `nil`); service passes it through; handler writes `{"players": []}` |
| More than 5 players match | `LIMIT 5` in the SQL query hard-caps results; the service never sees more than 5 rows |
| Request has no or invalid Authorization header | `middleware.Auth` returns 401 before the handler is invoked |
| `q` contains SQL wildcard characters (`%`, `_`) | Service escapes `%` → `\%` and `_` → `\_` before passing to repo; query uses `ESCAPE '\'`. No injection risk (parameterised query). |
| `q` contains accented characters (e.g. searching "Mbappe" to find "Mbappé") | Both sides wrapped in `unaccent()` — `unaccent(name) ILIKE '%' \|\| unaccent($2) \|\| '%'`. Match succeeds. |
| Very large `team_flag` SVG in response | No server-side size limit. At 5 results and ~48 teams per tournament this is acceptable. |
| Concurrent searches | Stateless read-only query; no concurrency concerns. |

## 8. Open Questions

~~1. **`players.id` type**~~ — **Resolved: UUID**, consistent with all other tables.

~~2. **Accent/diacritic insensitivity**~~ — **Resolved: yes**, via `unaccent` extension + functional GIN index on `unaccent(name)`.

4. **`team_flag` size limit**: No DB constraint is proposed. If response bloat becomes a concern (5 results × large SVGs), a separate endpoint for serving flags on demand could be introduced later. Decide whether to add a `CHECK (octet_length(team_flag) <= 65536)` constraint now.

5. **Response fields**: `external_id` and timestamps are excluded from `playerResponse`. Confirm with the frontend: does any prediction payload need to reference the api-football player ID directly? If so, expose `external_id` in the response.

6. **Empty `q` behaviour**: The plan returns 400 for `q=""`. An alternative is 200 with an empty array. Decide which is preferred for client UX.

## 9. sqlc Query Shape

```sql
-- name: SearchPlayers :many
SELECT id, name, team_name, team_flag
FROM players
WHERE tournament_id = $1
  AND unaccent(name) ILIKE '%' || unaccent($2) || '%' ESCAPE '\'
ORDER BY similarity(unaccent(name), unaccent($2)) DESC
LIMIT 5;
```

The service escapes `$2` before passing it (replacing `%` → `\%`, `_` → `\_`), so the `ESCAPE '\'` clause applies cleanly. `ORDER BY similarity(...)` ranks closest matches first without needing an extra index — similarity is a byproduct of the trigram GIN scan.
